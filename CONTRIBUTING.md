# Contributing to Live Audio Transcription

Thank you for considering contributing! This guide covers how this project actually works — the setup, the architecture invariants that must never regress, and the review etiquette this repo has learned the hard way.

## Project at a Glance

| File | What it is |
|---|---|
| `live_transcription.py` | Main app: audio capture → buffer window → backend → overlay / console |
| `whisper_backends.py` | Backend abstraction: whisper.cpp server (GPU), faster-whisper (CPU), `auto` (state machine) |
| `live_transcription_lite.py` | Console-only version, zero arguments |
| `benchmark.py` | Times inference through `create_backend()`; recommends `--buffer` / `--slide` |
| `speech_gate.py` | Silero VAD wrapper; skips buffers with no speech before they reach a backend |
| `safe_paths.py` | The one answer to "may this caller name that file?" — both `wave.open` sinks go through it (invariant 20) |
| `start_whisper_server.cmd` | Starts the whisper.cpp GPU server (`_whisper.cpp\whisper-server.exe`) |
| `console.py` | The session log under `logs/`, and hiding the launcher's console once a panel is up (invariant 17) |
| `run_pipeline.cmd` / `Start Transcription.vbs` | Guided launcher / double-click shortcut |
| `presets/builtin/*.json` | Shipped VAD profiles — the launcher's Speech / Music / Off, as presets both panels can load |
| `SETUP_AMD.md` | AMD/Vulkan walkthrough; README's "Building whisper.cpp" is the general one |

Runtime layout (gitignored, not part of the repo):

```
_whisper.cpp/   whisper-server.exe + DLLs (Vulkan or CUDA build)
_models/        GGML .bin models (GPU server) + faster-whisper model folder (CPU fallback)
_state.json     The panel's remembered choices (settings.REMEMBERED) — currently
                just server_model. Delete it and the defaults come back.
```

## Development Environment

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

Working on the desktop panel (`ui/`) additionally needs the **.NET 8 SDK**,
once, to run `.\build_ui.cmd`; merely *running* the panel needs only the
Desktop Runtime, because the build output is committed under `ui/runtime`.
`ui\tools\shot.py` renders every tab to a PNG for review (`--light` for the
light pair, `--runtime DIR` to review a publish that is not `ui/runtime`
yet), and `ui\tools\soak.py` is the leak soak — 90 minutes by default, run
it before building more UI on top of a binding-layer change (`--minutes 5`
smoke, `--minutes 240` release gate; exit 0 passed, 1 failed, 2 not judged).
Both were first run on real hardware on 2026-08-23 — PENDING_WORK.md steps
6 and 8 record what that found, including why the duration came down from
four hours and why the verdict judges private bytes rather than the working
set. `global.json` pins the build to an 8.0 SDK (see invariant 11): the
newest installed SDK (10.x) would otherwise rewrite `ui/runtime`'s
`deps.json` and `runtimeconfig.json` against the committed output.

**Never publish into `ui/runtime` while a soak is running.** It is not only
that the DLL is locked — a .NET assembly is memory-mapped and paged in
lazily, so replacing it mid-run silently mixes two builds into one process
and every number after that point is meaningless. That happened on
2026-08-23 and cost the run. Publish to a scratch directory and point
`shot.py --runtime` at it until the soak ends.

To run against the GPU backend:

1. `start_whisper_server.cmd ggml-medium-q5_0.bin` (no argument = default `ggml-base-q5_1.bin`)
2. Wait until the server responds: `curl -s -o NUL -w "%%{http_code}" http://127.0.0.1:8080/` → `200`
3. `set PYTHONUTF8=1` then `.venv\Scripts\python live_transcription.py`

**Why `PYTHONUTF8=1`?** Captions print the `→` character (U+2192), which does not exist in the Windows cp1252 console encoding. On a plain console the worker thread raises `UnicodeEncodeError` and dies *silently* — the app keeps running with no captions. Run from Windows Terminal or set the env var.

## Architecture Invariants (do not regress)

Each of these fixes a real bug we found in review. A PR that weakens one needs a strong justification.

1. **Trim *before* transcribe.** The window handed to `transcribe()` must be bounded (max `BUFFER_LENGTH_SEC + 2*BUFFER_SLIDE_SEC`). Trimming after drain-and-append, or leaving the buffer unbounded, makes latency feed on itself — measured 4.1 s → 53.2 s of backlog on a slow GPU. The worker drains the queue, bounds the window, *then* transcribes.
2. **Error backoff.** Log the first 3 consecutive errors, then every 10th. The backend layer counts failures per session; per-line logging floods the console when a server dies.
3. **The sliding window's overlap is trimmed per WORD, against the previous window's full decoded text.** Two halves, and the first one is what this invariant used to say on its own: compare against the previous window's *whole* segment set, not just its last line, and remember what the window **decoded** rather than what it printed — a window's own trimmed-off head was still spoken inside it, so the next window overlaps that too. The second half is what a keep-or-drop filter could never do. A whisper server cuts segments where its own caption wrapping says, which has no relationship to where the audio was cut, so the repeated speech comes back **fused to the new speech inside one segment**: measured against a live `whisper-server` over `tests/fixtures/speech_sample.wav`, window 2 of `--buffer 4 --slide 2` returned the single segment `"Silerow decides whether this buffer contains speech."`, of which the first four words were printed by window 1. A filter whose only moves are keep and drop has no way to say "print the second half of this", so it printed the lot. It could not catch the whole repeats either — window 1's `"over the lazy dog."` scores **0.57** against window 0's `"the quick brown fox jumps over the lazy dog."`, because difflib's ratio is over the sum of both lengths and the previous line is the longer one, against a shipped `--dedup-threshold` of 0.80. Over twelve windows the old filter fired **zero** times and printed 98 words where 56 were spoken. The trim aligns this window's words against the previous window's and cuts at the far edge of the furthest shared run that **reaches the previous window's end** — the tail is the anchor, because that is where the overlap provably ends. Anchoring on both ends does not work: whisper re-decodes the overlap differently either side of a cut, so difflib routinely splits it in two (`"a gap only ends"` at the head, `"it has"` at the tail, at `--buffer 4 --slide 1`) and neither run touches both ends. `OVERLAP_SLACK` (2 words of the previous tail may go unmatched) is measured — 0 and 1 leave 49 and 11 repeated words against 10, and 3 and 4 change nothing — and a one-word run is believed **only** corner to corner, because an interior single match is coincidence that cost three words of real speech in the measurement. Words printed / duplicated / lost, before → after, on `ggml-base-q5_1`: 4/2 `98/32/0` → `59/3/0`; 4/1 `146/63/0` → `63/4/0`; 6/2 `128/60/0` → `58/2/0`; 3/2 `74/15/0` → `57/3/0`; 8/4 `67/17/5` → `51/1/5`. On `ggml-large-v3-turbo-q8_0` the bug is *worse* before and the fix better after — 4/2 `99/33/0` → `57/2/0`, 4/1 `155/76/0` → `58/3/0`, 6/2 `121/43/0` → `57/2/0` — because a more fluent decoder fuses longer segments. **No geometry loses a word to the trim** (the five at 8/4 are lost before the filter sees them; the old filter loses the same five). Three things it must not become: it must not use word **timestamps** — the same word moves 0.3–0.7 s between decodes of the two windows, and cutting on the geometric overlap edge instead lost 1–8 real words per geometry; it must not take the *worse* of a text and a timing cut, which reached zero duplicates by eating 5–11 real words; and the whole-segment test must stay, on what survives the trim, because it is the only thing `--dedup-threshold` reaches — it fires on nothing now, and a shipped setting that changes nothing is worse than no setting. Trimming rewrites a caption, so `Segment.retext` is what rebuilds it: `translated` is a measurement of what the backend did with this audio (invariant 16) and survives, while `words` are cut at the **word** boundary the tokenizer's leading space marks, never at a token index — `"Silero"` is three tokens. Finally, the remembered text follows the audio: `reset()` drops it, because once the buffer is gone the next window is adjacent to nothing and a word-level trim could only eat a phrase that happened to coincide — while `configure()` deliberately keeps it, since a setting re-tuned mid-sentence leaves the previous window still adjacent to the next. That rule had no caller for as long as it existed: `Pipeline.start()` calls `strategy.reset()` now, and deliberately not `_build_strategy()`, which `_drain_pending` reaches too — "rebuild to match the settings" and "this is a new session" are different questions and only `start()` can answer the second. Measured, a Stop holding 3.0 s of audio and then a Start put those 3.0 s at the front of the first new window, so it straddled the gap, and matched the first caption of the new session against a window however long the stop lasted away from it — with the same sentence said twice, the whole new caption disappeared. `tests/test_pipeline_restart.py` pins it from both directions, because moving that one call breaks one of them. `tests/test_overlap_filter.py` pins all of it on segments the real server returned. `tests/test_console.py` covers the session log that replaced the two console windows (invariant 17) — it opens no window and hides none, testing `hide()` only at the contract a test runner can give it.
4. **AutoBackend state machine** (`--backend auto`): 5 consecutive failures → fall back to CPU; probe the server every 60 s (3 s timeout); failures are counted *per server* so a broken CPU model can't flip back to a dead server; a sticky local error stays on CPU.
5. **Explicit device-index validation.** `speakers[-1]` would silently select the last device via Python's negative indexing — always range-check before indexing.
6. **bat parsing.** Inside `( )` blocks cmd expands `%VAR%` at parse time; paths containing `)` break the block. Keep the existing quoting patterns, and read `%ERRORLEVEL%` outside the block.
7. **Language is normalized in one place.** `normalize_language()` in `whisper_backends.py` is the only thing that decides what "detect it" means, because the backends disagree: the HTTP API wants the string `"auto"`, faster-whisper wants `None` and raises `ValueError` on `"auto"`. Codes are validated up front for the same reason — whisper.cpp accepts `english`, faster-whisper does not, so an unvalidated code runs fine on GPU and kills transcription the moment `auto` falls back to CPU. Every backend stores the normalized value and re-spells it at the call site. The same applies in the other direction: whisper-server *reports* a full name (`english`) where faster-whisper reports a code (`en`), so `language_code()` maps both to the code before it reaches a caption — otherwise the label changes mid-session on an auto fallback.
8. **Never normalize per chunk.** Capture hands the worker raw audio; the window is scaled once, immediately before inference. Peak-normalizing each ~128 ms block destroys the only evidence the silence threshold and the VAD have — measured, quiet room tone goes from `0.0064` (correctly below the threshold) to `0.2214`, against speech at `0.2279`. It is also a per-chunk AGC that pumps gain inside a single word.
9. **Silero needs its 64-sample context.** Both ONNX export styles declare a dynamic input shape and will happily accept a bare 512-sample hop — then return near-zero probability for everything, which is indistinguishable from "no speech" and silently stops the transcript. Frames must be `64 + 512`. `speech_gate.py` builds them in one place for exactly this reason. For the same family of reasons `create()` must run the model once before returning it, and `analyze()` must never raise into the caller — `analyze()`, not `speech_frames()`, is what the strategies actually call (`buffering.py` lines 258 and 491; `speech_frames()` and `has_speech()` are views onto it): the worker calls it *outside* the `try/except` that guards `transcribe()`, so a model that loads and then throws kills the worker thread and leaves the app running with no captions and nothing in the log. Input names identify an export but do not prove it runs — upstream ships streaming models both with and without an `sr` input, and feeding an undeclared input is a hard `InvalidArgument`.
10. **The threshold and the frame count are not one knob.** Do not collapse `--vad-threshold` and `--vad-min-speech-ms` into a single "sensitivity" setting — they separate different things, and only one of them separates music from noise. Measured, frames over `0.5` per 4-second window: speech `66 70 66 67 74 78 36 83 74 35 97`, music with vocals `2 3 2 11 2 6 7 15 0 5`, room tone and fan hum `0` in every window. Lowering the *threshold* moves every source toward passing together (at `0.05`, music reaches 3/6 windows and room tone 2/6 — no useful gap). Lowering the *frame requirement* works precisely because steady noise scores zero: `60 ms` admitted 9/10 music windows with noise still at 0/6. That measurement is the source of the `60` in `run_pipeline.cmd`'s Music option **and** in `presets/builtin/2 Music.json`; if it is ever re-derived, both move together.

    Since the hysteresis knobs were wired up, `--vad-threshold` is load-bearing in *two* places and this is the second reason not to reach for it: it is the admission threshold, and it is also where the end-of-speech threshold comes from whenever `--vad-neg-threshold` is `0` — which is the default, because `_tune` reads `0` as *derive it* (`threshold - 0.15`, floored at `0.01`) and keeps the requested and effective values apart so the derivation follows a later threshold change instead of freezing. Lowering the threshold to admit singing therefore also drags down where speech is reported to *end*, which is what `silence_at_end_of_chunk` and `best_cut()` work from. Lowering the frame requirement touches only the admission half.

    **Every gate setting must reach both call sites in `_build_gate`.** `--vad-neg-threshold` and `--vad-min-silence-ms` shipped inert: they validated, declared `rebuild="gate"`, logged and echoed to both panels, and were passed at neither `SpeechGate.create()` nor `gate.configure()`, so the app silently ran `create()`'s own defaults instead. That is worse than a dead knob — `create()` still had `min_silence_ms=160` after the default was deliberately moved to 400 (see UPSTREAM_MINING.md), so the panel showed 400 while the gate ran the value the repo documents as wrong. A `Field(...)` whose `rebuild` target does not consume it is not wired up, and nothing else in the chain will say so. Measured on `tests/fixtures/speech_sample.wav` (six SAPI sentences spliced with 0.30 s word gaps and 0.85 s sentence gaps - `tests/make_speech_sample.py`): segments 12 / 12 / 8 / 6 / 6 / 6 / 5 / 2 / 1 at `--vad-min-silence-ms` 100 / 160 / 250 / 320 / 400 / 500 / 800 / 900 / 1200, and through the real `silence_at_end_of_chunk` at `--chunk-length 2.0 --chunk-offset 0.1`, 10 chunks at 160 ms against 6 at 400 ms and 1 at 1200. At the default `--chunk-offset 0.4`, 160 and 400 tie at 6: the offset floors both above the word gaps. The first measurement of this showed 8 against 6 at that offset, and the two extra chunks were the bug invariant 15 describes, not the knob.
11. **After any `ui/` change: `.\build_ui.cmd`, then commit `ui/runtime`.** The desktop panel's publish output is committed so a fresh clone runs it with only the .NET Desktop Runtime — no SDK, no restore, no network. Nothing enforces the rebuild but this line: a PR that edits `ui/*.cs` or `ui/*.xaml` without a matching `ui/runtime` diff ships a panel that silently does not contain the change. (`.\build_ui.cmd` with the leading `.\` — cmd does not resolve a bare batch name.) `global.json` at the repo root pins the build to the 8.0 SDK band (`rollForward: latestFeature`, so any installed 8.0.x is accepted) — keep it. Without it `dotnet` takes the newest installed SDK, and a 10.x SDK rewrites `ui/runtime`'s `deps.json` and `runtimeconfig.json` (it prunes framework-provided packages and swaps a `configProperties` key) — a diff with no source change behind it. With the pin, a rebuild after a source edit changes `LiveTranscription.Ui.dll` and nothing else; if `git diff --stat ui/runtime` shows more than that, the wrong SDK built it.
12. **Bridge methods return promptly and never touch the window.** Everything in `wpf_panel.py`'s `EngineBridge` runs ON the WPF dispatcher thread holding the GIL; slow work goes through `App._lifecycle`, and state goes back in through `PanelHost.Post*` / `Panel.event`, which marshal asynchronously. A blocking `Dispatcher.Invoke` from a bridge method — or joining the panel thread from a bridge method, which is what `Panel.close()` does — is the one deadlock this architecture can produce; `_request_exit` uses `Panel.request_close()` for exactly that reason.
13. **The settings pane stays generated.** Adding a `Field(...)` to `settings.py` must make a control appear in *both* panels with no UI edit. Anything that special-cases a key by name in `ui/Settings` or `webui/app.js` is a hole in that; there is exactly one sanctioned hole (`model`, rendered as a picker over `_models` — both panels make the same exception, see `SettingsVm.SetModels`). It is still exactly one: `server_model` is a picker over `_models` too and needed **no** exception, because it is declared `choice` with the dynamic source `ggml_models` and is found by that source rather than by key (`SettingsVm.FieldWithSource`, `choicesFor` in `webui/app.js`). That is the pattern a new dynamic list follows — `model` is a `path` only because on the command line it is one, and copying its special case instead would widen the hole rather than use the mechanism that already exists. A new field *kind* is different: it needs a template in `ui/Views/FieldTemplates.xaml`, a case in `FieldTemplateSelector`, and the kind added to `SettingsVm.KnownKinds` — the startup assert fails loudly listing exactly these three places until all of them exist. The same rule decides where a setting that changes the *window* is applied: `wpf_theme` is read by `app.py` (`_sync_panel_theme`, next to `_sync_overlay`), which tells the panel "dark" or "light" through `Panel.theme()` - C# never sees the key.

14. **A shipped preset states every key its family owns, even at the default.** Presets apply as a *patch* — `_preset_load` hands the file straight to `pipeline.apply`, and keys the file omits keep their current value. So `presets/builtin/2 Music.json` carries `"vad": true` and `3 Off.json` carries `"vad_min_speech_ms": 250` even though those are the defaults, and deleting them as redundant is the bug: a Music file listing only `vad_min_speech_ms` cannot switch the gate back on after Off, and an Off file that leaves `60` behind arms Music invisibly the next time Silero is re-ticked by hand (`show_if` hides that field while the gate is off). The Save button **cannot** regenerate these files — `save_preset` stores only non-default values, so it would strip exactly the keys that make them work. Hand-author them, and treat the union of keys as the unit.

15. **The end of the buffer is not the end of speech.** Live audio ends wherever capture stopped, so the last run the gate sees is usually still open, and `GateResult` holds two rules for it that `silence_at_end_of_chunk` cuts by (`speech_gate.py`, "What the end of the buffer means"). *An open run ends at the buffer edge, not where a pending quiet stretch began.* A gap that has not yet lasted `--vad-min-silence-ms` is, by the gate's own rule, not the end of speech; reporting its start as `last_speech_end` let `--chunk-offset` alone decide when the talker had stopped - told to wait 832 ms, the gate reported the gap on the frame it began and the strategy cut in it after 416. At the defaults (400 ms, 0.4 s) the two coincide to the frame, which is why nothing showed. *An open run is never dropped for being shorter than `--vad-min-speech-ms`.* That filter judges complete runs; an open one has only a length so far, and a word 190 ms in is not a click. Dropped, `last_speech_end` fell back to the previous segment and the strategy cut through the word: at 160 ms the sample was cut at 25.09 s, 0.19 s into its last sentence, because a 6-frame open run lost to `min_frames` 8. So a chunk is cut once the gate has closed the last run *and* `--chunk-offset` of quiet has passed since it ended - the later of the two. The no-speech skip honours the same rule from the other side: a buffer that is quiet until a word starts in its last frames scores under `min_frames`, and the skip drops only the quiet, keeping the open run (bounded at `min_frames` by `_open_run_start`, so a silent stream still cannot grow the buffer) to open the next chunk on the word's first frame rather than its eighth. `tests/test_speech_gate.py` (`EndOfBuffer`) and `tests/test_silence_strategy.py` pin all three rules on scripted probabilities.

16. **A caption is labelled translated only if it came back translated.** `translated` on a transcript entry was `bool(settings["translate"])` — the checkbox — so the front ends' `ja -> EN` tag was a restatement of the request that could not disagree with itself, and a model which ignored the translate task produced Japanese captions labelled as English with nothing in the app able to notice. It is a measurement now (`Pipeline._translated`), from two independent pieces of evidence, and only ever downgraded: what the backend says it *did* (`Segment.translated` — whisper-server reports `"task"` in `verbose_json` **after** its own overrides, so it is also what catches an English-only model, which the server silently switches translation off for; faster-whisper echoes the task it ran), and what came back (`looks_untranslated()` — a caption containing kana, hanzi, hangul, Cyrillic, Greek, Hebrew, Arabic, Devanagari or Thai cannot be the English translation it claims to be). The second test is the only thing that catches `large-v3-turbo`, which accepts the task and transcribes: measured against a live server with `-l ja -tr`, turbo returns Japanese where `large-v3` and `base` return English. It cannot catch a Latin-script source — French decoded as French reads as English to it — so do not present it as a general translation check. Neither test may ever *promote* a caption to translated: absence of evidence (an older server that omits `"task"`) leaves the request's own answer standing. The warning is once per backend, not once per caption. A `Segment` is a tuple subclass and cannot be edited, so everything that changes one builds another, and the answer has to survive every route that reaches `__new__` a second time: `retext` carries it explicitly (invariant 3), and `__getnewargs__` lists **every** parameter of `__new__`, `translated` included. `copy` and `pickle` restore the instance `__dict__` over whatever `__new__` built, so they came back correct even while `translated` was missing from that list — which is why it went unnoticed — but rebuilding from those same args by hand returned `None` for a caption the backend said it translated. `tests/test_translate.py` pins all of it, with no model and no server.
17. **A panel means the console is not the front end — but it is still the only thing that reports a crash.** Started from the launcher, this used to put three windows on screen: `run_pipeline.cmd`'s own console, which asks the setup questions and then hosts Python; a second console holding whisper-server; and the panel. Only the third is a user interface. Both consoles are gone for the `--web` and `--wpf` paths now, and every step of removing them has a rule attached.
    * **The server goes through `start_whisper_server.cmd`, not `whisper-server.exe`.** `app.py` launches the same .cmd with `CREATE_NO_WINDOW`, `stdin=DEVNULL` and a pipe. Calling the exe directly would mean a second copy here of the default model name, the path checks and the `STATUS_ILLEGAL_INSTRUCTION` explanation, all three of which the .cmd owns. `stdin=DEVNULL` is what makes that work: the .cmd ends in `pause`, which with no console to read from would block forever holding an invisible process, and on EOF returns at once — measured at **0.02 s** on the model-not-found path, with every line of its diagnostics arriving down the pipe. `CREATE_NO_WINDOW` also keeps the good half of the `CREATE_NEW_CONSOLE` it replaced: a handle whose lifetime is the server's, not a launcher's that exits in milliseconds.
    * **The server's output has two sinks, and they are not the same output.** The session log gets every line; the panel's Log tab gets only what arrives *before* the server first answers. That is where the Vulkan/CUDA device list is, which SETUP_AMD.md tells you to check. After it, whisper-server prints four lines per REQUEST (`system_info:` and `operator (): processing 'buffer.wav'`, with a blank either side) — measured over one 26 s file at the default slide: **103 lines, 96 of them that** — which at a 2 s slide is two lines a second into the panel forever. `_server_ready` is the switch, set the moment the server answers.
    * **Hide the console only once a front end is actually up, and always put it back.** `_start_wpf` and `_start_server` both degrade to "the panel is off; transcription carries on" and say so in a print; hiding before that turns a missing .NET runtime into a process with no window *and* no panel, which is worse than three windows. `console.hide()` additionally refuses unless `console.capture()` is holding the output, because a hidden console with nothing teeing it is output thrown away rather than moved. And it must come back: cmd is still sitting behind Python and will run its "safe to close this window" and its own `pause` when Python exits, into a window nobody can see, waiting for a keypress nobody can give it. `restore()` runs from `shutdown()` and from `atexit`.
    * **`--start-server` is deliberately not a `Field`.** Every Field generates a control in both panels (invariant 13), and "start the server I am already running inside of" is only sayable before the process exists — a tickbox for it would do nothing whichever way it was set. The console modes still get the separate server window, because there is no panel to put the log in and the console they would share is the transcript.
    `tests/test_console.py` pins the tee, the rotation and the refusal to hide with nothing catching the output.

18. **Remembered state is an allow-list, not a settings file.** Everything else here is a default, a named preset or a flag someone typed, and that is deliberate: nothing about a run is hidden state you cannot read in a file you chose to write. `_state.json` is the one exception, and `settings.REMEMBERED` is what keeps it one — it currently holds exactly `server_model`, and a key is added to it on purpose or not at all. **Do not turn this into "remember whatever changed."** The exception is earned by a specific property, not by convenience: `server_model` is the only setting whose value is spent *outside* this process. whisper-server reads its model once, at startup, so choosing one is not "change a number the running engine picks up" but "launch a different program" — which is also why its `rebuild` tag is `engine` — nothing to tear down; it lands on the next Start or Restart, and `Pipeline.apply` **discards** it alongside `restart` and `overlay`. That discard is not cosmetic: the tag matches no branch in `_drain_pending`, but left in the set it still makes `if rebuild:` true and pushes a `state` document for a rebuild that never happened. Note that `pipe._rebuild` reads empty either way — `_drain_pending` empties it on its way through — so the test asserts on the *emitted events* instead; an undiscarded no-op tag emits `['state', 'settings', 'log']` where a discarded one emits `['settings', 'log']`. A new tag must also join `settings.REBUILDS`, which validates nothing and so fails silently as documentation and why `_remember_model` writes on the launch rather than once the server answers, since the large models this exists to keep are exactly the ones that miss `ENGINE_START_WAIT_SEC`. Precedence is **defaults < remembered < preset < flags**: naming a preset or typing a flag is a statement about *this* run and must not be overruled by what the panel was doing last time. The two lookups are also deliberately asymmetric — `App._boot_model` downgrades a model that is no longer in `_models` to the launcher's default and says so, while `_engine_start` *refuses* an unknown name, because there the name came from a browser (invariant: "run this batch file with these arguments" is not something a browser gets to say freely). A remembered file that has since been deleted must never be able to stop the engine from starting. `tests/test_settings_state.py` pins the allow-list and all four precedence steps with no WPF, no model and no audio; `tests/test_panel.py` (`EngineModel`) pins the panel half.

19. **`REMOTE_LOCKED` is a security control, so its membership is a test, not a comment.** This list spent a while being three lies: `settings.py`'s own comment said a page "must not be able to point `--model` at an arbitrary path", `Pipeline.apply`'s docstring said `remote=True` refuses "the model path", and `README.md` promised users the same — while `model` was not in the tuple. Three documents asserting a control that did not exist is worse than none, because it is the state in which nobody goes looking. `tests/test_remote_locked.py` now asserts the membership itself. **Add a key when it is the only untrusted route to a sink of its kind** — that is why `model` (a non-directory string is not an error but a `download_model()` fetch, then a CTranslate2 weight load), `vad_model` (the tree's only `InferenceSession`) and `output` (the tree's only `makedirs` + `open` for writing, reachable with no start command because `apply` drains synchronously when nothing is running) are on it. **Do not add a key for symmetry.** `file_path` is deliberately absent and there is a test saying so: locking it would disable `capture="file"` in the browser while removing no capability, because the benchmark *command* carries its own wav path into `wave.open` and never passes through `apply` at all — a lock on settings is not a lock on a capability. `server_model` is absent for the opposite reason: `_engine_start` basenames it and checks it against the real `_list_models()` listing, so it has no sink. Two mechanics that look like details and are not: the pop happens **before** `validate()`, which matters because `validate()` itself touches the filesystem (the `capture="file"` rule stats `file_path`, and on Windows a UNC value makes that stat an outbound SMB authentication); and the same `remote=True` path carries **preset files**, so a locked key cannot come in through a preset either — which is why the refusal message names where a setting *can* be set rather than saying "not from the browser". The desktop panel passes `remote=False` and is unaffected by design (`wpf_panel.py`); never "fix" that by locking at the wrong layer.


20. **A read path is checked by shape at the sink, never by locking a key.** `REMOTE_LOCKED` settles the write side by naming keys; it cannot settle the read side, because a wav path reaches `wave.open` by **two** doors and only one of them is a settings patch — `file_path` through `Pipeline.apply`, and the `wav` argument of the benchmark **command**, which no filter on patches ever sees. So the rule lives in `safe_paths.check_read_path()` and both doors call it (`FileSource`, `benchmark.load_wav`), with `Pipeline.apply` and `Pipeline.benchmark` checking early as well — early because `validate()` stats `file_path`, and on Windows stat-ing a UNC path *is* the outbound authentication being refused. **Trust is a parameter, not a property of the path.** There is no safe path, only a path that is safe for a given caller: someone at the keyboard may transcribe a WAV on a NAS, a browser client naming a host path may not. `trusted=False` is the default so a call site added later and not thought about gets the careful answer; the CLI and `wpf_panel` say `trusted=True` out loud, and `Pipeline._untrusted` tracks which keys' *current values* came off the socket, because by the time `_build_source` reads the string it looks identical either way. **Rules that cost nothing are unconditional; the one that costs a capability is not.** No UNC, no device names (`CON.wav` is the console *with* the extension on), no data streams, `.wav` only — none of that removes anything a browser could legitimately do. Folder containment does, so `Pipeline._audio_roots` charges it only once the listener is bound off loopback, and `LAT_AUDIO_ROOTS` widens it. That knob is an environment variable and not a `Field` on purpose: policy limiting the browser must not itself be one patch away from the browser. Two traps found by writing the tests rather than by reading the code, both pinned in `tests/test_safe_paths.py`: Windows still hands out 8.3 short names (`%TEMP%` is `C:\Users\ICECRE~1\...`) while `realpath` expands the file to its long form, so roots must be `realpath`-ed too or containment fails **shut** on the owner of the machine — which looks exactly like containment working; and an ordering test that asserts a spy saw *nothing* passes just as well when the spy was never wired to anything, so it carries a positive control.

21. **The fallback backend must not need the thing it is falling back from.** `LocalBackend` can run on CUDA now, and `local_device` still defaults to **`cpu`**. That is not timidity: under `backend="auto"` this backend is reached *because* whisper-server just died, and the most common reason it died is the GPU — driver reset, VRAM exhausted, another process holding the card. A fallback that loads on CUDA fails for the same reason the thing it replaced did, and `AutoBackend._local_error` is **sticky** by design (retrying a broken model would stall the worker for seconds on every pass, forever), so one failed load costs the session its CPU path for as long as it runs. `"auto"` therefore means *try cuda, settle for cpu* inside `LocalBackend` rather than *cuda if a card is present*, and CTranslate2's own `device="auto"` is deliberately not used — it raises when it picks cuda and the runtime is absent, which is the one outcome this path cannot afford. `"cuda"` never silently degrades, because asking for the GPU and quietly getting the CPU is indistinguishable from the GPU being slow. The counterpart rule is about honesty in the UI: the field was labelled "CPU model path" and the constructor hardcoded `device="cpu"` — true on the Radeon Pro W5500 this project started on, where CTranslate2 genuinely has no GPU path, and a lie on every NVIDIA machine since. When hardware assumptions get baked into a **label**, nobody re-examines them. Also note what is *not* validated here: `local_compute` is passed to CTranslate2 untouched, because that enum is theirs and a copy of the accepted values in this repo would eventually contradict the real one. `tests/test_local_device.py` pins the order of attempts (not just the outcome) with a fake `WhisperModel`, and pins that the CUDA-runtime error names the two pip packages — the raw message names `cublas64_12.dll`, which a CUDA 13 Toolkit does not supply and cannot be made to. Two measured traps live here, and both produced a *confidently wrong* answer before being measured. **A cuda model that loads is not a cuda model that works:** the wheels put `cublas64_12.dll` in `site-packages\nvidia\cublas\bin`, which is on no search path, and Python 3.8+ dropped `PATH` from the DLL search order for extension modules — so the model constructs happily on cuda and dies on the *first inference*. `_add_cuda_runtime_to_path` fixes it by prepending to `PATH` and **not** with `os.add_dll_directory`, which was tried first and does nothing here: it only affects `LoadLibraryEx` calls passing the search-path flags, and CTranslate2 asks by bare name. **And never time a single inference:** cuBLAS/cuDNN init plus Blackwell kernel JIT lands entirely on the first call, which measured CUDA at 10.45 s against the CPU's 7.78 s — the GPU looking 34 % *slower* than the CPU it is 4× faster than. With one warm-up discarded the same pair is 8.09 s CPU / 1.89 s CUDA. `benchmark.py` has always discarded a warm-up rep for exactly this reason; anything measuring a backend must do the same.

## Testing Expectations

- **`python -m unittest discover -s tests -t . -v` is the committed suite.** It runs without onnxruntime or a model: `tests/fakes.py` stands a `SpeechGate` on a session that reads each frame's probability straight off the audio level, so the state machine, `GateResult`, `configure()`, both `_build_gate` call sites, the `apply()` path and `silence_at_end_of_chunk` are all tested on scripted probabilities in whole 32 ms frames. `tests/test_real_model.py` runs the real Silero weights against `tests/fixtures/speech_sample.wav` and skips itself unless both exist; `python tests\make_speech_sample.py` builds the fixture with Windows SAPI (gitignored - six sentences with known 0.30 s and 0.85 s gaps, so the ladder has a ground truth). A change to the gate or the chunking strategy adds a case here before it adds a number to a docstring. `tests/test_translate.py` covers the translate-labelling path end to end on a fake `requests` (invariant 16). `tests/test_pipeline_restart.py` covers the stop/start round trip: the backend and the capture source are stubbed and everything else in `start()` runs for real, because the ordering between them is the point — a new session starts the strategy from nothing, and a mid-session rebuild still does not. `tests/test_overlap_filter.py` is the sliding window's half (invariant 3): every window in it was captured from a live `whisper-server` over the same fixture, so the wording is the model's own — including the mistakes, since recognising `"speech"` against `"beach"` either side of a cut is the job. It needs no server, no model and no audio, because `filter()` is handed the segments directly, which is what `pipeline.py` does with what the backend returned. `tests/test_panel.py` is the desktop panel's half: it opens the real window from the published `ui/runtime` (so after a `ui/` change, `.\build_ui.cmd` first), binds app.py's own preset and settings handlers under the real `SettingsVm`, and asserts the toasts and the theme the window actually shows - the preset-ack bug that toasted success on every refusal was invisible to both `shot.py` and `soak.py`, which render and measure but assert nothing. It skips without pythonnet or the .NET Desktop Runtime (`.venv\Scripts\python.exe -m unittest tests.test_panel -v` runs it; the window is on screen for a few seconds). `tests/test_settings_state.py` is the other half of invariant 18 and skips nothing — it needs no WPF, no model and no audio, so the allow-list and the defaults &lt; remembered &lt; preset &lt; flags order are checked on every machine even where the panel tests cannot run. Both redirect `settings.STATE_FILE` into a temp tree: a test that leaves `_state.json` in the checkout changes what the next real launch starts on. `tests/test_remote_locked.py` and `tests/test_safe_paths.py` are the two security halves (invariants 19 and 20) and both `chdir` into a temp tree for the same reason — turning `save` on builds a real writer, and with no `output` set that drops a `transcript_*.txt` in the checkout on every run, gitignored so it never shows up as a diff to notice. The read-path tests are also written so a regression fails an assertion instead of reaching for the network to find out: with the guard removed the suite takes **3.0 s instead of 0.04 s**, and those three seconds are Windows resolving `\\attacker.example\share\` — the attack, timed. `tests/test_local_device.py` (invariant 21) substitutes a fake `WhisperModel` so it can assert the *order* faster-whisper is asked for a device in, which is the part that matters and the part an outcome-only test cannot see; it loads no model and needs no GPU, so it runs everywhere.
- **Empirically verify behavior changes.** PR #1 was won on evidence, not opinions: a fake whisper-server for backend tests (zero model downloads), stub audio drivers, and real runs against a real server + model.
- **Latency claims need numbers** — windows/sec, `infer_s` vs `--slide`, before/after. "Feels faster" doesn't survive review.
- **The AutoBackend test suite** (55-clock-fake tests) was written during development but never committed. Adopting it, or writing your own equivalent, is welcome.
- **GPU-specific behavior needs a real GPU run.** Don't claim "holds real time" without a measured `infer_s`.

## Git Workflow & Branching

- **Never submit a PR from `main`.** Create a dedicated branch: `feature/...` or `fix/...`.
- **One PR = one change.** A single feature or bug fix; no unrelated edits mixed in.
- **Keep `main` green.** Housekeeping (docs, license, CI) can land on `main`; behavior changes go through review.

## Review Etiquette

- **Draft PRs until the code is final.** Convert to "Ready for Review" only when you're done.
- **No mid-review pushes.** Once a reviewer has started, don't push new commits except in direct response to feedback — continuous updates invalidate existing code suggestions and waste the reviewer's time.
- **Test locally before opening.** If it doesn't run on your machine, it doesn't go up.

## Responsible AI Code Generation

If you use AI tools to assist your development:

- **You are responsible for what you push.** If you can't explain the logic, syntax, or architecture of your PR, it will be rejected.
- **No live AI-prompting on open PRs.** Iterate with your AI locally, on your own machine, before opening the PR.
- **Verify before claiming.** AI suggestions that touch the invariants above need the same empirical proof as anything else.
